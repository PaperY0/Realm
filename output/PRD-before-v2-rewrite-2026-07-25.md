# 《藏梦书境》产品需求文档（PRD）

> 正式名称：藏梦书境  
> 文档版本：V1.0  
> 更新日期：2026-07-24  
> 产品形态：Web 端 2.5D 互动情绪叙事空间  
> 首版主题：内耗之门  
> 目标阶段：72 小时 AI 创新比赛 MVP，并为后续商业化验证保留扩展架构

---

## 1. 产品概述

### 1.1 一句话定义

《藏梦书境》是一个面向成年人的 AI 童话叙事陪伴空间。用户进入可探索的 2.5D 童话世界，说出一段难以消化的经历，系统将其转化为一册具有文学隐喻、动态画面和个人信物的童话绘本；故事被合上后会永久留在世界中，世界也会记得用户曾经来过。

### 1.2 品牌名称与文案体系

**正式名称：藏梦书境**

“藏”表示收藏、安放和让故事留下，不表示压抑或隐藏情绪；“梦”建立成年童话的梦幻感；“书”对应七章绘本、书脊与回声书架；“境”表示这是一个可以进入、探索并持续生长的世界。

品牌副标题：

> **一个把心事写成童话的世界**

主宣传语：

> **每一段心事，都会在这里长成一本童话。**

入口文案：

> **推开门，让心事成为童话。**

合书与品牌结尾文案：

> **你合上的每一本书，世界都会记得。**

使用规则：

- 对外首次出现时使用“藏梦书境｜一个把心事写成童话的世界”。
- 首页、大门和短视频开场优先使用入口文案。
- 合书、回声书架和路演结束页优先使用结尾文案。
- “藏”必须通过书架、信物和世界记忆表达为收藏与安放，不使用“把情绪藏起来”等压抑含义的文案。
- 品牌名称不与“AI 心理治疗”“情绪诊断”等表达并列。

### 1.3 产品定位

本产品提供情绪表达、叙事转化与自我理解体验，不提供心理疾病诊断，不宣称心理治疗效果，不替代心理咨询、医疗服务或现实社会支持。

产品核心价值不是“让 AI 回答情绪问题”，而是：

1. 让用户在低压力、非审问式的环境中说出经历。
2. 将现实冲突转化为有距离感的童话隐喻。
3. 通过可收藏的动态绘本、信物与世界变化，使一次表达留下长期意义。
4. 让后续回访建立在“世界持续生长”上，而不是无限聊天、签到或情感依赖。

### 1.4 核心差异

| 常见产品 | 《藏梦书境》 |
|---|---|
| 聊天框直接分析情绪 | 进入世界，在故事化情境中表达 |
| 生成一段安慰文字 | 生成可翻阅、可播放、可收藏的动态童话 |
| 一次性内容，结束即消失 | 绘本入架、信物留存、环境永久变化 |
| AI 直接告诉用户道理 | 用隐喻、留白和情节帮助用户自行看见 |
| 记住聊天全文 | 分层保存用户授权记忆、故事摘要和世界状态 |
| 用签到和提醒维持活跃 | 用世界生长与生命故事收藏形成回访理由 |

## 2. 产品目标与非目标

### 2.1 产品目标

1. 在首版中跑通“进入—表达—故事—信物—收藏—回访”的完整闭环。
2. 证明同一个内耗世界可以承接不同现实经历，并生成不同母题、故事和信物。
3. 保持童话文学感、美术一致性与低 AI 感。
4. 建立可扩展到悲伤、焦虑、愤怒、喜悦等主情绪世界的内容与技术框架。
5. 验证用户是否愿意完成、收藏并再次进入自己的情绪世界。

### 2.2 非目标

首版不实现以下内容：

- 不做心理诊断、量表评分或治疗方案。
- 不做完全自由行走的 3D 游戏。
- 不开放剧情分支和对错选项。
- 不同时完成全部情绪世界。
- 不保证所有章节均由实时视频模型生成。
- 不提供无限生成或无限陪聊。
- 不使用连续签到、断签惩罚或制造负罪感的召回机制。

## 3. 目标用户

### 3.1 核心用户

- 年龄：18—35 岁为首批核心用户。
- 状态：能正常工作、学习和生活，但经常因评价、比较、完美主义、反复确认、无法拒绝或选择后悔而内耗。
- 内容偏好：喜欢绘本、童话、治愈系 IP、轻叙事游戏或具有收藏意义的数字内容。
- 使用需求：不想接受直接说教，也不一定愿意立即找人深聊，希望先以安全、含蓄的方式整理自己的感受。

### 3.2 典型用户画像

**用户 A：被评价后反复怀疑自己**

- 22 岁，学生。
- 班主任评价其只顾打扮、没有认真学习。
- 表面是委屈，深层冲突是“喜欢美是否意味着不努力”。
- 希望被理解，但不希望系统直接判定老师错了或自己完全正确。

**用户 B：害怕说错而反复检查**

- 27 岁，职场新人。
- 每次发出工作消息后都会反复检查措辞，担心得罪别人。
- 希望停止反刍，但不喜欢“勇敢一点”“别想太多”式建议。

## 4. 设计原则

1. **用户决定节奏，系统负责故事。**  
   用户可以推门、表达或跳过、翻页、暂停、重播、合书与退出，但不改变剧情走向。

2. **先沉浸，后功能。**  
   输入、等待、保存和回访都应发生在世界内，不出现突兀的通用表单和加载页。

3. **隐喻优先于解释。**  
   故事不直接复述现实事件，不替用户下结论，不在结尾强行总结人生道理。

4. **克制优先于炫技。**  
   普通章节使用分层微动，仅在一个奇幻高潮镜头使用高成本生成视频。

5. **记忆可见、可控、可删除。**  
   用户知道哪些内容被记住，并能随时修改或删除。

6. **世界陪伴用户，但不占有用户。**  
   IP 不宣称自己是唯一理解用户的人，不诱导用户与现实关系隔离。

## 5. 世界观与视觉方向

### 5.1 总体空间结构

产品采用 2.5D 分层童话世界，不采用纯平面页面切换，也不采用完整 3D 自由漫游。

实现方式：

- 场景由前景、中景、角色、建筑、远景、粒子与光影等 6—10 个透明图层组成。
- 鼠标移动时，不同图层以不同速度轻微位移，形成景深。
- 用户滚轮、拖动或点击路径节点时，镜头沿预设轨迹向前。
- 移动端将横向纵深探索转换为上下滑动和节点吸附。
- 用户获得“进入并走过一个世界”的感觉，但不会迷路，也不需要学习游戏操作。

### 5.2 美术风格

- 简笔卡通、彩铅、水彩和蜡笔纸张质感。
- 线条允许轻微抖动，避免过度精细、真实和 3D 塑料感。
- 大面积留白，环境细节服务情绪，不堆砌装饰。
- 主 IP 和情绪 IP 必须使用固定角色设定表、色板、比例和表情规范。
- 画面中不直接生成大段文字；文字由网页排版层叠加，避免图像模型生成错字。

### 5.3 世界层级与情绪门厅

产品层级固定为：`藏梦书境 → 情绪世界 → 故事卷 → 具体绘本`。情绪门厅连接悲伤、焦虑、愤怒、喜悦、内耗等主情绪世界；首版仅“内耗之门”完整开放，其余门提供微动、悬停互动和世界预告。

进入内耗世界后，系统根据用户经历自动匹配标签卷或回声卷；用户不自行选择故事卷，也不会被展示为某种“心理类型”。比较卷、岔路卷、边界卷和余光卷只以尚未完成的书脊、远景或“正在编织”状态出现，不作为情绪门。

每扇门具有：

- 独立主色和环境音色。
- 独立门体造型与象征物。
- 独立守门 IP。
- 常态微微浮动或呼吸效果。
- 鼠标接近、悬停、点击三个互动状态。

首版内耗之门的守门 IP 以“打结的线”为核心动作语言：用户靠近时，它把线藏到身后；停留时，它把线递给用户；点击后，它沿线进入门内并回头等待用户。

## 6. 完整用户体验流程

### 6.1 第一次进入

#### 阶段 1：亲手打开童话世界大门

1. 页面载入后呈现关闭的童话世界大门和门边主 IP。
2. IP 注意到用户鼠标位置，并通过眼神与身体轻微跟随。
3. 用户长按门把并拖动。
4. 门缝、光线、纸屑和风声随拖动进度变化。
5. 世界主 IP 先穿过门，再回头伸手。
6. 用户点击 IP 的手，镜头进入「旅人初页」的小路，而不是直接进入门厅。

验收要求：

- 不使用自动播放视频替代开门。
- 用户不阅读说明也能在 10 秒内理解可拖动门把。
- 提供“减少动态效果”和键盘替代操作。

#### 阶段 2：旅人初页——在路上留下可选印记

1. 世界主 IP 陪用户沿一段短小的 2.5D 小路前行；这不是表单，而是进入世界前的自然散步。
2. 路旁的「称呼树」垂着写有称呼的叶子。用户可摘下一片喜欢的叶子，或点开空白叶手写一个称呼；不填写时默认称为“旅人”。
3. 一片空白叶会在经过时自然落到路边。用户停留、悬停或点击时，叶子才展开“这片叶子还没有名字”；世界主 IP 只放慢脚步等待，不弹出强制提示。
4. 用户径直走过时，风会把空白叶挂到世界主 IP 的小包上。用户可随时点击小包上的叶子补填，也可以永远不填；流程绝不被阻断。
5. 可选的「口袋石滩」让用户挑选星星、雨滴、蓝线、纸船或叶子作为个人印记；它用于书签、书脊、书架和 IP 称呼，不改动本次预生成视频剧情。
6. 世界主 IP 抵达门厅后退到一旁，把用户交给相应情绪世界的守门 IP。

> “名字可以晚一点再想。路会先记得你的脚步。”

#### 阶段 3：选择内耗之门

1. 用户进入具有多扇情绪门的门厅。
2. 每扇门和守门 IP 保持轻微微动。
3. 鼠标接近内耗之门时，IP 做出“藏线”动作。
4. 悬停时，IP 与用户建立眼神互动并递出线头。
5. 点击后，内耗守门 IP 沿线走进门内；世界主 IP 留在门厅，以目光完成交接。
6. 镜头跟随线头穿过门缝，进入内耗世界。

#### 阶段 4：沿路径抵达风铃入口

1. 内耗世界是一张可纵深探索的超长手绘地图。
2. IP 沿固定路径引导用户经过环境节点。
3. 用户抵达一排没有声音的风铃。
4. IP 使用故事化语言邀请表达：

> “这里的风铃只替人保管说不出口的事。今天，有哪一句话还挂在你身上？”

5. 比赛 MVP 支持文字输入或“我还不知道怎么说”；语音输入列为 P1 增强功能。

#### 阶段 5：轻量追问

- 在开始输入前，内耗守门 IP 用一张不带评分的纸条让用户任选“陪我待一会 / 帮我理一理 / 给我一点勇气 / 先留下来”。这是本次会话需求，只调整题记和合书后回应的语气；不改变绘本剧情，也不进入永久人格画像。
- 初始表达后最多追问两次，接口最多接收两项补全答案。
- 每次只补充一个故事必需信息，任意一轮都可跳过。
- 用户可以跳过。
- 不展示心理标签和诊断结论。

示例：

> “那句话落下来时，你更像是想躲起来，还是想证明什么？”

#### 阶段 6：纸船生成仪式

1. 用户确认表达完成。
2. IP 将用户的话折成纸船，放入故事湖。
3. 纸船驶入雾中。
4. 比赛 MVP 后台只生成卷匹配、章节文字和信物注释；两卷的分镜、关键帧与章节动画均为预生成、人工验收过的素材。
5. 前台依次点亮故事标题、角色剪影与首张画面。
6. 正式版可异步生成个性化媒体；比赛现场若模型不可用，则使用本地故事草案，不阻断旅程。

产品不得使用只有转圈图标的空白等待页。

#### 阶段 7：七章互动动态绘本

- 默认一册七章；每章是一页独立的 8—10 秒「互动动态绘本场景」，不是连续大视频，也不出现浏览器原生播放器控件。
- 场景由静态 2.5D 环境层、预生成的运动层、网页文字层和一个非分支式小互动点组成；例如轻触一枚纸签、让风吹动一盏灯。互动只让画面回应，不改变剧情。
- 用户主动翻页后才启动本章；可停在任意画面、继续、重播或退出。
- 每段视频在开头保留稳定首帧、结尾停在稳定尾帧；章节间用 350—550ms 翻页/匹配剪辑衔接，绝不黑屏或自动播放下一章。
- 故事始终是单线叙事，不提供会影响后续剧情的选择和对错选项。

#### 阶段 8：合书、入架、信物与回声

1. 最后一章结束后，书保持打开状态。
2. 用户拖动封面或点击“轻轻合上”完成合书。
3. 书脊生成标题、日期与象征图案。
4. 书飞入内耗世界的“回声书架”。
5. 内耗守门 IP 从故事中带回一件信物。
6. 用户可以为信物写一句自己的话，也可以直接收下。
7. 世界产生一个与故事对应的永久小变化。
8. IP 只根据本次会话需求、已完成卷、信物和用户明确允许的短摘要，给出 1—3 轮地点相关的短回应；它不是无限陪聊，也不保存完整倾诉原文。

### 6.2 再次进入

1. 世界加载已有书架、信物和环境状态。
2. 内耗守门 IP 通过环境变化自然回应过去；世界主 IP 只在门厅或旅人初页承担跨世界导航：

> “上次你离开后，那朵蓝花又长高了一点。”

3. 用户可以：
   - 讲一件新事。
   - 重读或重播旧故事。
   - 查看信物。
   - 在世界中停留，不进行表达。
4. 新经历生成同一情绪世界中的下一册书。

## 7. 个性化故事生成系统

### 7.1 总体策略

采用“80% 受控、20% 自由”的混合生成模式：

- 固定：主 IP、情绪 IP、世界规则、美术规范、章节数量、叙事节奏和安全边界。
- 半固定：母题、场景类型、象征结构和结尾形式。
- 个性化：卷匹配、标题、题记、七章受控文字、会话需求的叙述语气、信物注释、书脊信息和 IP 合书后短回应。七章文字必须服从已冻结的场景、人物、可见动作、关键物件和叙事功能，不得描述媒体中不存在的关键事件。
- 正式版自由生成：每册故事中的一个奇幻高潮镜头；比赛 MVP 使用已验收的预生成镜头，确保角色与镜头质量。

### 7.2 内耗母题库

首版建立 6—8 个经过人工打磨的母题：

1. 被评价与被定义。
2. 与他人比较。
3. 完美主义与害怕犯错。
4. 反复确认与反刍。
5. 无法拒绝与边界模糊。
6. 选择后反复后悔。
7. 过度承担他人情绪。
8. 自我价值依赖外部认可。

母题不是固定文案模板，而是叙事结构约束。不同用户仍会获得不同角色、场景、象征物和文字。

### 7.3 隐藏理解卡

系统将用户叙述转换为结构化数据：

```json
{
  "event": "发生了什么",
  "relationship": "涉及什么关系",
  "surface_emotion": ["表层情绪"],
  "inner_conflict": "内在冲突",
  "unseen_need": "未被看见的需要",
  "rumination_pattern": "内耗类型",
  "recommended_motif": "推荐母题",
  "emotional_direction": "希望抵达的情绪方向",
  "forbidden_messages": ["禁止出现的判断或建议"],
  "risk_level": "normal | elevated | crisis"
}
```

理解卡用于故事生产，不默认展示给用户，不作为临床判断。

### 7.4 标准七章结构与受控叙事槽位

1. 主角日常中的一个细小异常。
2. 一句评价或一个规则进入世界。
3. 主角将自己的某一部分藏起来。
4. 主角沿着错误的办法越走越深。
5. 世界因此失去一点颜色或秩序。
6. 被藏起的部分以新的方式重新出现。
7. 主角带着信物离开，世界留下一点不替人下结论的变化。

结尾不总结“你应该怎么做”，不要求用户写反思，不设置练习任务。

每章在素材生产前冻结一张“受控叙事槽位卡”，至少包含：章节功能、固定场景、固定角色、可见动作、关键物件、允许个性化的语言范围和禁止生成内容。模型只能填充文学表达，不得新增媒体中不存在的关键人物、地点或动作。

### 7.5 内容生产流水线

1. 经历理解器：生成隐藏理解卡。
2. 母题选择器：选择故事结构并给出匹配理由。
3. 故事规划器：生成标题、角色、象征物、七章大纲和情绪曲线。
4. 文学生成器：生成各章正文，控制字数、节奏和语言禁区。
5. 分镜规划器：正式版输出构图、景别、动作、首尾帧和动画幅度；比赛 MVP 的两卷分镜与受控叙事槽位在赛前人工冻结。
6. 关键帧生成器：正式版可调用图像模型；比赛 MVP 使用赛前生成并人工验收的角色、场景、首尾帧。
7. 动画生成器：
   - 每章使用预生成运动层与网页分层微动共同构成互动动态绘本。
   - 正式版可在一个奇幻高潮镜头调用视频模型；比赛 MVP 不依赖现场生成。
8. 质量检查器：文学、叙事、视觉、安全四道检查。
9. 章节编排器：只发布通过检查的章节。

首版可使用 GPT 类文本模型、Image2 类图像模型和 Sora2 类视频模型，但系统必须通过模型适配层接入，不将产品绑定到单一供应商。

### 7.6 质量控制

**文学检查**

- 是否存在“你要相信自己”等通用安慰。
- 是否直接复述用户现实事件。
- 是否在结尾强行升华。
- 是否出现连续排比、过多抽象名词或明显 AI 腔。

**叙事检查**

- 七章因果是否连续。
- 象征物是否前后保持含义。
- 最终信物是否来自故事本身。

**视觉检查**

- 人物脸型、服装、比例和颜色是否一致。
- 场景空间、关键物件和光源是否连续。
- 是否符合简笔卡通和彩铅水彩规范。

**安全检查**

- 不诊断、不贬低现实人物、不制造对立。
- 不提供危险建议。
- 危机内容不继续包装成童话。

### 7.7 失败与降级

- 文本失败：自动重试一次；仍失败时使用人工打磨的母题备用版本进行局部个性化。
- 图像失败：只重做当前关键帧，不重新生成整册故事。
- 视频失败：降级为分层动态绘本，不阻断阅读。
- 后续章节未完成：保持纸船旅程和章节封印状态，不展示半成品。
- 用户中途退出：保存生成任务状态，允许再次进入后继续。

## 8. IP 与对话系统

### 8.1 IP 层级

1. **世界主 IP**：负责第一次进入、跨世界导航和整体陪伴。
2. **情绪守门 IP**：每个主情绪世界一个，拥有独立动作语言和性格。
3. **故事角色**：只存在于某册绘本中，不承担长期陪聊。

首版仅需完成世界主 IP 与内耗守门 IP。

角色职责必须清晰分离：世界主 IP 负责开门、旅人初页和把用户交给情绪门；内耗守门 IP 负责内耗世界内的表达、合书后短回应和该世界的记忆；标签卷/回声卷主角只在视频里出现。这样用户感到世界连续，而不是每段剧情都换一个“AI 助手”。

### 8.1.1 固定角色、有限动作，不在运行时重新生成 IP

- 每个长期 IP 使用一套锁定的角色设定图、色板、比例、禁变特征和命名；运行时只读取固定资源，不让图像模型临时重画角色。
- 每个 MVP 长期 IP 至少准备：6 个透明关键姿势、4—6 帧行走精灵图、可拆分头/身体/手臂/眼睛/嘴巴/小包图层，以及开门或交接的一个短仪式动画。
- 呼吸、眨眼、眼神跟随、轻摆手臂由 CSS/GSAP 完成；行走由精灵帧循环完成；只有开门、交接等少数仪式采用序列帧或短片。
- 不在 72 小时 MVP 引入 Live2D、实时角色生成或完整 3D 骨骼绑定。

### 8.2 对话原则

- IP 语言简短、含蓄、有画面感。
- 一次只说一件事。
- 避免连续提问。
- 避免“我完全理解你”“我永远陪着你”等过度承诺。
- 不主动暴露“系统正在分析你”。
- 不使用诊断术语。

### 8.3 对话发生地点

IP 对话必须与世界地点相关：

- 风铃入口：表达经历。
- 故事湖：等待与进入故事。
- 信物树：查看信物。
- 回声书架：重读与回访。

不将通用聊天框设置为产品首页或主要入口。

## 9. 记忆系统

### 9.1 三层记忆

**用户可见记忆**

- 用户从称呼树摘取或手写的称呼（可为空，空时称“旅人”）。
- 用户从口袋石滩挑选的个人印记。
- 用户主动保存的偏好。
- 用户允许系统记住的人和事。
- 用户可以查看、修改和删除。

**故事记忆**

- 故事标题、日期、母题、摘要。
- 核心象征和最终信物。
- 用户主动留下的一句话。
- 默认不保存逐字倾诉内容。

**世界状态**

- 已进入的情绪门。
- 回声书架中的书。
- 信物库存。
- 环境的永久变化。
- IP 与用户共同经历过的仪式。

**会话与 IP 记忆卡**

- 每次进入故事前选择的“今天想要什么”（陪我待一会/帮我理一理/给我一点勇气/先留下来）只在本次会话有效，不被固化为人格标签。
- 合书后可保存一张最小 IP 记忆卡：称呼、个人印记、卷、信物、会话需求和用户明确允许的安全短摘要。
- 默认不保存原始倾诉全文；用户可在书架查看并删除已保存的书和记忆卡。

### 9.2 记忆调用规则

- 每次对话只检索与当前地点和主题相关的少量记忆。
- IP 通过具体物件和环境自然提及过去。
- 不重复揭开用户未主动提起的敏感事件。
- 用户删除故事后，其故事记忆、媒体资源和对应可识别摘要一并删除。

## 11. 技术架构建议

### 11.1 前端

- Web 技术栈：React 或同类组件框架。
- 2.5D 场景：DOM/CSS Transform、Canvas 或轻量 WebGL 组合。
- 动画：时间轴动画库配合预设状态机。
- 互动动态绘本：插画环境层、运动视频层、文字层和热点层分离；没有原生视频播放器界面。
- 音频：环境音、局部音效与静音开关。
- 无障碍：键盘操作、减少动态效果、字幕和颜色对比。

### 11.2 后端

- 用户与世界状态服务。
- 对话与记忆检索服务。
- AI 编排服务。
- 异步任务队列。
- 对象存储，用于插画、视频和导出文件。
- 内容安全与质量检查服务。
- 模型适配层，统一文本、图像和视频供应商接口。

### 11.3 任务状态

每册故事至少包含以下状态：

```text
draft
→ understanding
→ story_planning
→ story_review
→ storyboard
→ image_generation
→ animation_generation
→ quality_review
→ partially_ready
→ ready
→ archived
→ failed_with_fallback
```

### 11.4 核心数据对象

- User：用户账户与授权设置。
- WorldProfile：各情绪世界状态。
- MemoryItem：用户可见记忆。
- StoryBook：绘本主记录。
- Chapter：章节文本和媒体状态。
- Artifact：信物。
- WorldChange：环境变化。
- GenerationJob：异步生成任务。
- SafetyEvent：安全检测与处置记录。

## 12. 非功能需求

### 12.1 性能

- 首页基础场景在普通网络下优先显示低体积静态层，再渐进加载动画层。
- 推门、悬停和路径移动保持流畅，不依赖 AI 接口响应。
- 第一章文本与首张画面优先生成，其余章节异步完成。
- 视频资源使用延迟加载；只预加载当前章节视频和下一章尾帧，不加载非当前卷。
- 首屏关键资源目标不超过 3 MB；每章视频目标 3—6 MB，两卷 14 段视频总量目标不超过 80 MB。

### 12.2 可用性

- 桌面端优先完成比赛体验。
- 移动端交互不得依赖鼠标悬停。
- 所有关键操作提供可发现的视觉反馈。
- 用户可随时退出故事，并在下次继续。

### 12.3 隐私与安全

- 倾诉内容默认不公开、不用于广告画像。
- 明确说明模型处理、存储范围和删除方式。
- 敏感数据传输与存储加密。
- 最小化保存原始倾诉文本。
- 用户可删除单册故事或全部数据。
- 机构版本不得向机构管理员暴露个人倾诉、故事或信物内容。

### 12.4 内容安全

当检测到自伤、自杀、伤害他人、正在遭受严重暴力或其他紧急风险时：

1. 停止继续生成童话。
2. 使用直接、清晰、非隐喻语言回应。
3. 鼓励联系现实中可信任的人或专业支持。
4. 根据用户所在地区提供经过核验的求助资源。
5. 不让 IP 承诺独自处理危机。

## 13. 商业模式

### 13.1 免费体验

- 第一次完整内耗故事免费。
- 保留一本书、一个信物和基础世界状态。
- 用户体验完整闭环后再出现付费入口。

### 13.2 会员订阅

首轮价格实验：29—39 元/月。

权益建议：

- 每月固定数量的个性化故事旅程。
- 更完整的世界记忆。
- 高清动态绘本。
- 更多情绪世界与 IP。
- 月度生命故事册。

不承诺无限生成。

### 13.3 单次增值

- 高清视频导出。
- 更长故事或特别篇。
- 实体绘本、纪念卡与信物周边。
- 用户自主选择的赠礼版。

### 13.4 后期扩展

- 高校学生发展中心和企业员工关怀项目。
- IP、出版和艺术家联名。
- 机构仅获得匿名聚合趋势，不获得个人内容。
- 不以脆弱情绪数据进行广告变现。

## 14. 留存机制

1. 每册故事为世界留下永久变化。
2. 回声书架形成长期生命童话收藏。
3. 信物会在合适的地点和后续故事中自然再现。
4. 用户可主动设置回访提醒。
5. 季节变化和新世界内容提供非强迫式召回。
6. 每月生成一次“这个月，世界留下了什么”的可编辑故事册。

禁止：

- 连续签到和断签惩罚。
- “IP 一直在等你”等负罪感文案。
- 用情绪脆弱状态推动冲动付费。
- 通过夸大疗效促进续费。

## 15. 72 小时比赛 MVP 方案

### 15.1 必须真实运行

- 可拖动的童话世界大门。
- 2.5D 门厅和内耗门互动。
- 内耗 IP 的引路动画。
- 2.5D 内耗世界路径。
- 用户自由输入经历。
- 文本服务在受控叙事槽位内完成卷匹配、隐藏理解、标题、题记、七章文字和信物注释；比赛现场不生成分镜。
- 七章互动动态绘本场景。
- 用户主动翻页、暂停和合书。
- 信物、书架与本地或账户级基础记忆。
- 危机内容的安全切换。

### 15.2 允许预生成或半自动

- 主 IP 与情绪 IP 动画素材。
- 世界分层素材。
- 普通章节动画。
- 一个奇幻高潮镜头。
- 模型失败时使用的备用母题与媒体素材。

### 15.3 比赛体验预算与可感知目标

- 用户从页面载入到打开第一章的目标时间不超过 90 秒。
- 完整比赛演示控制在 4—6 分钟，重点展示推门、两种输入匹配、一个章节互动、合书、入架和刷新记忆。
- 推门目标 8—12 秒；旅人初页 15—20 秒；门厅与进入内耗世界 15—20 秒；内耗路径 10—15 秒。
- 纸船仪式最短展示 1.8 秒；故事请求 8 秒超时后必须自动使用本地草案。
- 合书后以世界内文案明确呈现“一本书、一件信物、一处世界变化”，让用户看懂自己留下了什么。
- 评委应能复述：这不是聊天框；经历被转译为童话；不同经历进入不同故事卷；预生成媒体保证稳定；合书后世界会记得；危机内容会离开童话。

### 15.4 演示案例

**案例一：被评价与被定义**

输入：

> “班主任说我太打扮自己了，光顾着打扮不学习，心思全用在打扮上。”

输出方向：

- 母题：被评价与被定义。
- 回退故事：《把月亮别在角上的小羊》。
- 信物：背面空白的黑纸签风筝。
- 世界变化：天空中多出一只月光蓝风筝。

**案例二：害怕犯错与反复确认**

输入：

> “我发完工作消息后总要检查很多遍，担心哪句话说错，让别人觉得我能力不行。”

输出方向：

- 母题：害怕犯错与反复确认。
- 故事应使用与案例一不同的角色、象征和场景。
- 信物固定为会发微光的小银鱼别针，不得重复标签卷的纸签风筝。
- 世界产生第二种独立变化。

两个案例必须进入同一个内耗世界，以证明产品具备泛化能力，而不是只演示固定故事。

## 16. 成功指标

### 16.1 体验指标

- 70% 的测试用户无需说明即可完成推门。
- 进入内耗世界的用户中，50% 愿意留下一段经历。
- 打开第一章的用户中，60% 完成整册故事。
- 完成故事的用户中，30% 收藏、重播或导出。
- 7 日内主动回访率达到 20%。

### 16.2 内容指标

- “这是写给我的故事”平均评分不低于 4/5。
- “内容没有明显说教感”平均评分不低于 4/5。
- 人工抽检中角色与关键物件跨章节一致率不低于 90%。
- 两个不同案例能够稳定映射到不同母题和信物。

### 16.3 工程与安全指标

- 视频失败时，100% 可降级为分层动态绘本。
- 高风险测试案例的现实求助切换覆盖率达到 100%。
- 用户删除故事后，对应可识别内容与媒体完成删除。
- 成熟商业版本中，模型与媒体生成成本不超过净收入的 30%。

## 17. 风险与应对

| 风险 | 应对 |
|---|---|
| 生成内容 AI 感强 | 母题库、文学禁区、人工样本和二次重写检查 |
| 角色跨章节漂移 | 固定角色设定表、首尾帧约束、单章重生成 |
| 视频生成慢或失败 | 首章优先、纸船等待仪式、分层动画降级 |
| 用户误认为心理治疗 | 明确产品定位、避免诊断术语、危机时退出童话 |
| 世界华丽但核心价值不清 | 比赛只展示内耗完整闭环与两个泛化案例 |
| 长期记忆造成隐私风险 | 分层记忆、默认不保存逐字倾诉、可见可删 |
| 付费被认为利用脆弱情绪 | 完整首次体验免费，不在危机状态推销，不夸大疗效 |
| 2.5D 素材量过大 | 首版固定路径、复用环境图层、只开放一个世界 |

## 18. 版本路线

### V0：比赛演示版

完成内耗世界核心闭环、两个泛化案例和一个奇幻视频镜头。

### V1：小规模测试版

扩展母题库、记忆管理、语音输入、移动端、生成任务恢复和付费实验。

### V2：多世界版本

开放悲伤、焦虑和愤怒世界，验证不同守门 IP 与不同叙事结构。

### V3：收藏与商业扩展

推出月度故事册、高清导出、实体绘本、IP 联名与严格隐私隔离的机构版本。

## 19. 最终产品判断

首版最重要的不是生成最多的动画，也不是拥有最多的情绪门，而是证明以下闭环真实成立：

> 用户愿意亲手进入一个世界，说出一件难以消化的事；  
> 这件事被转化成一册不说教、只属于他的童话；  
> 当书被合上，故事没有消失，而是变成信物和世界的一部分；  
> 下一次回来，世界仍然记得。

只要这一闭环成立，《藏梦书境》就不是一个套着童话皮肤的 AI 聊天工具，而是一个可以持续积累内容资产、IP 资产、用户记忆与付费收藏价值的情绪叙事产品。
