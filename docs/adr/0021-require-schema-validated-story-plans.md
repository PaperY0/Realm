# 文本规划必须通过 Schema 校验后才能冻结

V0 中用于模型间传递的 SafeStoryBrief、StoryBible、StoryTemplateMatch、BoundaryKeyframePlan 和七张 ChapterCard 必须输出为结构化数据并通过应用层 Schema 校验。用户可见的正文可以保持文学语言，但工作流不得依赖解析 Markdown 标题或一段自由故事文本来提取事实。

结构化输出首次校验失败时，只允许进行一次不改变故事事实的格式修复。修复后仍不合法，则阻断全部关键帧、正式视频与个性化降级章节生成；没有合法故事事实时不能生成或冒充一本完整绘本。只有完整故事包、八张边界关键帧规划和七张章节卡全部通过校验后，才将只读任务分发给七个章节生成器。

该规则不依赖中转站是否原生支持 JSON Schema；若上游模型没有严格结构化输出能力，应用层仍必须完成解析、校验和受限修复。该选择增加 Schema 设计与错误处理工作，但避免自由文本解析错误扩散为七个昂贵且互相矛盾的视频任务。

Schema 合法只是冻结条件之一；故事包还必须通过 ADR 0026 定义的独立叙事语义验收。
