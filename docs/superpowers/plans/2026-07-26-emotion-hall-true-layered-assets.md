# 情绪门厅真实分层门体改造计划

## 目标

将情绪门厅从“背景图上的点击热区”改为可独立渲染的真实分层场景：干净大厅作为底图，五扇门、五位守护 IP、门缝光效、浮动动画和点击区域分别存在；同时全局移除“减少动态”模式及其状态逻辑。保留当前交互约定：只有最左侧“内耗”门开放，其他门展示故事尚未开启的提示；点击内耗门进入 `expression` 路由。

## 实施步骤

1. **素材预处理与资源契约**
   - 将用户提供的无门大厅图复制为项目资源。
   - 从五门绿幕图抠出五张独立透明门体 PNG，并裁切到统一资源坐标。
   - 从守护者合成图提取五张独立透明正面角色 PNG，统一命名为 `overthinking`、`sadness`、`anxiety`、`anger`、`joy`。
   - 增加可重复执行的本地素材处理脚本，避免运行时使用 canvas 抠图。
   - 在 `server.js` 注册新资源路径，同时保留旧资源兼容已有页面。

2. **移除全局减少动态模式**
   - 从 `src/index.html` 删除减少动态控件。
   - 从 `src/app.js` 删除偏好键、状态字段、加载逻辑和事件监听。
   - 从 `src/styles.css` 删除 `.motion-toggle`、`body.reduce-motion` 和 `prefers-reduced-motion` 相关规则。
   - 清理测试与文案中对该模式的依赖，默认保留设计好的正常动态效果。

3. **情绪门厅 DOM 分层**
   - 使用无门大厅底图。
   - 每个门按钮内部放置独立门体、门缝光效、角色和阴影层。
   - 保留语义化按钮、键盘焦点、开放/未开放状态和对话卡片。
   - 删除对旧复合门厅背景的结构性依赖，确保五个视觉对象都能单独定位。

4. **分层动画与交互**
   - 门体、守护角色、门缝光效分别使用低幅度、错相位动画，形成真实的层次浮动。
   - hover/focus/selected 时仅增强当前门及其角色，不放大遮挡标题。
   - 未开放门维持“故事还在慢慢长成”的产品化提示；开放门点击后进入 `expression`。
   - 保持 16:9 场景比例、窄屏横向浏览和现有路由状态机。

5. **验证与验收**
   - 运行语法检查、门厅相关测试和完整 `npm.cmd test`。
   - 启动本地页面，在浏览器中确认五组独立图片层成功加载、动画存在、减少动态控件全局消失。
   - 实测未开放门不跳转、内耗门跳转到 `expression`，并检查桌面与窄视口不出现明显裁切。

## 验收标准

- DOM 中存在五组独立门体资源和五组独立守护者资源，不依赖单张五门复合图完成视觉呈现。
- 页面不再出现“减少动态”控件、状态或 CSS 分支。
- 五扇门在视觉上轻微错相位浮动，角色和光效与门体分层运动。
- 交互和路由保持：仅 `overthinking` 可进入 `expression`，其余门留在 foyer 并显示提示。
- 完整测试通过，浏览器实际加载资源无 404。
