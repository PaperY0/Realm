# 藏梦书境 V0 实施检查清单

> 用途：按“每次只实施一个明确步骤 → 提交证据 → 人工验收 → 再进入下一步”的节奏推进本机单实例 V0 Demo。
>
> 当前进度（2026-07-25）：**项目当前为 Web-only。世界大门视频入口、内耗之门、表达、最多两次追问、高风险浏览器拦截、SafeStoryBrief、Image 2 单图网关与探针已经实现；真实 `gpt-image-2` 成功图片尚未验证。完整七章、双重门禁、七图并行、2.5D 阅读器和合书入架闭环仍未完成。**

## 使用规则

- [ ] 每次开工前明确本步目标、允许修改范围和验收方法。
- [ ] 每次只推进一个步骤；未经人工验收，不自动进入下一步。
- [ ] 每次交付列出修改文件、删除文件及原因、运行命令、测试结果和未验证边界。
- [ ] 结构检查、静态检查、模拟数据和真实端到端结果必须明确区分。
- [ ] 不用预生成内容、占位图或假任务冒充本次真实生成结果。
- [ ] 发现 PRD、专项合同、Schema 或 ADR 冲突时暂停实现并先修正文档决策。

**验收门禁：**从打开页面到抵达表达入口形成完整可操作路径；跳过可选信息不阻断流程；移动端至少不崩溃。

## 第 5 步：表达、追问与安全处理

**状态：当前 Web Demo 范围已实现并有自动化检查；地区化危机资源与完整异常矩阵仍未完成。**

- [x] 实现文字表达、固定演示句和“我还不知道怎么说”。
- [x] 最多自然追问两次，每次只补一个故事必需信息且都可跳过。
- [x] 建立保守的工作流安全状态，不使用临床风险等级、诊断或人格判断描述用户。
- [x] 高风险文本在浏览器内拦截并清除，不创建 SafeStoryBrief、不发送图片请求；普通原始输入在 SafeStoryBrief 形成后删除。
- [x] SafeStoryBrief 使用表达与追问答案生成，并在浏览器请求前再次校验 `safetyStatus === story_safe`。
- [ ] 完善地区化危机资源展示和更完整的空输入、边界输入、中途退出与异常矩阵。

**验收门禁：**数据库、日志和错误页不残留不应保存的原始敏感输入；追问上限和跳过行为正确；危机输入不会创建故事任务。

## 第 6 步：七章故事包与双重门禁

**状态：未完成。当前只有 SafeStoryBrief，没有完整七章故事包、文本模型生成和双重门禁闭环。**

- [ ] 通过服务端统一 AI Gateway 调用固定文本模型，浏览器不直连中转站。
- [ ] 从 SafeStoryBrief 生成唯一内部 StoryTemplateMatch；标签卷/回声卷不在 UI 暴露。
- [ ] 由一个全局规划者生成并冻结 StoryBible、StorybookStyleGuide、ChapterIllustrationPlan 和恰好七张 ChapterCard。
- [ ] 先做 JSON Schema 结构校验，再做独立叙事语义校验；全部通过后才允许生成插画。
- [ ] 格式错误只做一次不改故事事实的受限修复；语义不合格只允许完整重规划一次。
- [ ] 不可靠匹配进入“暂不适配”，不私自增加第三套故事卷。

**验收门禁：**至少用“被评价/被定义”和“害怕犯错/反复确认”两类真实输入验证；七章均与本次输入相关，角色、信物、象征、因果与情绪递进连续；页面不显示内部路由或诊断性结论。

## 第 7 步：七张插画生成与人工审核

**状态：部分实现。服务端 `gpt-image-2` 单图网关与显式探针已完成；真实成功图片尚未验证，七图并行与逐章审核未实现。**

- [x] 浏览器只提交 SafeStoryBrief；服务端固定使用 `gpt-image-2` 和受限参考资产，密钥不进入浏览器。
- [x] 实现默认零请求检查和显式一次付费请求探针；无自动重试、无 fallback，失败不使用占位图。
- [ ] 获得并检查一张真实 `gpt-image-2` 成功图片，确认供应商链路、文件和视觉结果。
- [ ] 故事包通过门禁后，并行提交七张章节主插画任务。
- [ ] 每章都重新提供同一套守门 IP 参考资产、冻结视觉合同和对应 ChapterCard。
- [ ] 输出固定为 9:16、720×1280；画面不得含标题、正文、字幕、水印或无关文字。
- [ ] 建立逐章审核台：查看、批准、拒绝、单章重做、错误诊断和状态恢复。
- [ ] 未批准插画不得进入对应章节本地 2.5D；单章失败不得清空其他已通过章节。

**验收门禁：**七张插画与 I1–I7 一一对应；角色特征、服装、信物、反复象征、色光递进和绘本质感一致；刷新后审核状态仍在。

## 第 8 步：本地 2.5D 正式章节媒体

**状态：未完成。**

- [ ] 仅使用人工审核通过的主插画制作每章 5～8 秒动态预览。
- [ ] 每章最多一个主要镜头运动、2～3 层视差、最多两个局部微动，不增加人物、道具或剧情事实。
- [ ] 统一输出 720×1280、24 fps、MP4 / H.264 / yuv420p、无音轨、无内部切镜。
- [ ] 对容器、编码、尺寸、帧率、时长、黑帧、损坏文件和可解码性执行技术门禁。
- [ ] 单章失败只重试或重做该章，保留其他已通过资产。

**验收门禁：**七章本地预览全部可播放且不破坏人物结构、构图、笔触和纹理；它们被标记为默认正式媒体，而非“失败占位”。

## 第 9 步：七章互动绘本阅读器

**状态：未完成。**

- [ ] 只有七章故事、七张插画审核和七章本地预览全部通过后才进入可开书状态。

## 第 10 步：合书、入架、恢复与一键重置

**状态：未完成。**

- [ ] 最后一章后由用户主动合书，展示信物、地点相关回应和本次世界变化。
- [ ] 当前书进入回声书架；刷新、浏览器重开或服务重启后可恢复故事包、任务、审核、阅读/合书状态和媒体。
- [ ] 再次进入只能继续或重读当前书；生成新经历前必须先重置。
- [ ] 一键重置同时删除当前书数据库记录和对应媒体目录，不影响内置 IP、风格参考或故事模板。
- [ ] 删除前解析并校验绝对路径位于允许的媒体根目录内，防止越界删除。
- [ ] 世界记忆通过书脊、信物、地点和环境变化表达，不复述敏感原始输入。

**验收门禁：**刷新和重启均可恢复；重置后数据库与该书媒体同步清除；其他内置资产和目录不受影响；重置后可开始唯一一本新书。

## 第 11 步：可选 Seedance 增强（非 V0 闭环门禁）

- [ ] 只有对应章节插画人工批准且本地预览可用后，才允许逐章人工提交增强。
- [ ] 实现任务提交、状态轮询、结果下载、标准化、技术验收和终止失败处理。
- [ ] `queued`、`pending`、`processing` 不重复提交；首次提交 30 分钟后仍未终止则标记 `stalled` 并停止轮询。
- [ ] 供应商支持取消时主动取消；不支持时忽略迟到结果，防止覆盖已关闭或已重置任务。
- [ ] 移除供应商音轨；增强失败、停滞或质量不合格时继续使用本地 2.5D 正式媒体。

**验收门禁：**完全不调用 Seedance 仍能完成整书闭环；任何单章增强状态都不阻塞开书或破坏本地版本。

## 第 12 步：E2E 演练与交付整理

- [ ] 从空状态用真实网络、真实文本模型和真实图像模型完整生成并读完一本书。
- [ ] 记录从确认表达开始的各阶段时间；最长 5 分钟内满足“七章故事冻结 + 七图审核通过 + 七章本地预览可播”。
- [ ] 若超时，保留世界内等待与诊断界面，明确未完成章节；不得缺章开书或假装成功。
- [ ] 覆盖断网、模型超时、单章失败、刷新、浏览器重开、服务重启、重复点击、迟到任务和重置中断。
- [ ] 在 Windows 的 Chrome/Edge 1920×1080 全屏完成逐页视觉 QA，并验证 1366×768 可用性。
- [ ] 检查仓库无真实密钥、敏感原始输入、临时媒体、调试日志、重复产物和无用文件。
- [ ] 完成安装、启动、现场重置、故障恢复和演示流程说明；所有命令在干净环境实际验证。

**最终验收门禁：**8～10 分钟现场流程可闭环；七章故事和七张插画均来自本次输入；七章本地 2.5D 可播放；阅读、合书、入架、恢复和重置真实可用；失败不伪装成功；项目只保留运行、维护和验收所需资料。
