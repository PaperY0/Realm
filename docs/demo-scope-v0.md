# 藏梦书境 V0 比赛 Demo 范围

## 目标

在一台 Windows 演示电脑上，通过真实文本、图像和视频模型调用，完成“一次用户经历生成一本七章个性化绘本并逐章阅读”的端到端证明。当前交付不以正式上线、多人试用或商业运营为目标。

## 必须真实运行

- 浏览器完成用户输入、零至两次可跳过自然追问、等待仪式、开书、逐章播放、下一章、合书和重置。
- 本地 Node.js 服务端持有中转站 API Key；Key 不进入浏览器包、仓库或前端日志。
- 文本工作流真实生成 SafeStoryBrief、StoryTemplateMatch、StoryBible、BoundaryKeyframePlan 和七张 ChapterCard。
- 八张边界关键帧通过真实图像模型生成；失败时执行已确认的组合关键帧规则。
- 七章视频使用真实视频模型并行提交；失败或等待超过用户上限时执行个性化网页降级。
- 故事包和媒体都执行自动验收，不把人工审批放入用户链路。
- 页面刷新后能够恢复当前书的生成任务与已完成资产。
- 提供一键重置，清理当前书、运行状态和本地临时媒体。

## 运行边界

- V0 只展示内耗世界，不展示其他情绪世界入口或多世界选择页。
- 标签卷与回声卷只做内部路由，页面不提供选卷入口。
- 一次只运行一个浏览器演示会话。
- 一次只生成一本书；重置后才开始下一本。
- 服务端、任务状态和媒体资产都位于演示电脑。
- 演示使用真实网络与真实中转站 API，不以预生成素材冒充本次输入结果。

## 演示终端与视觉验收

- 唯一正式演示与视觉验收环境为 Windows 上的 Chrome 或 Edge 全屏窗口。
- 基准验收视口为 1920×1080；1366×768 只要求保持相同比例、布局完整且核心操作可用。
- 手机和平板不是本次视觉验收目标，只要求页面能够打开、不会崩溃，不承诺完整绘本体验。
- 完整章节视频和个性化网页降级共用同一个 16:9 绘本画面容器，不显示浏览器原生视频控件。
- 主角、信物、主要动作和重要视觉信息必须位于安全构图区，避免在不同桌面视口等比缩放时被裁切。

## 本次不实现

- 公网部署、域名、TLS 和生产运维。
- 注册、登录、账户找回和跨设备同步。
- 多用户并发、水平扩容和分布式锁。
- Redis、消息队列、云对象存储和 CDN。
- 生产级监控、告警、审计后台和运营后台。
- 支付、订阅、额度购买和商业化功能。
- 三十天服务端留存的生产定时清理任务。

## 保留但不作为 Demo 验收项

之前确认的隐私边界、三十天资产留存、主动删除和正式危机资源策略继续作为未来产品约束保留，但本次只实现与单机 Demo 直接相关的最小删除、安全和密钥保护能力。
## 本地状态与媒体存储

- 使用单个本地 SQLite 数据库保存当前绘本、文本规划、关键帧任务、章节视频任务、验收结果、重试次数和降级状态。
- SQLite 只保存状态、标识符、必要元数据和相对文件路径，不把图片或视频保存为数据库 BLOB。
- 关键帧、章节视频和临时文件保存在按 bookId 隔离的本地媒体目录。
- 七个章节任务分别更新自己的数据库记录，避免多个异步任务共同覆盖一个 JSON 状态文件。
- 页面刷新后，本地服务端从 SQLite 和媒体目录恢复当前生成进度。
- 一键重置清除当前书的数据库记录，并删除对应媒体目录；不影响应用内置的守门 IP 和模板素材。
## 声音与文字层

- 本次不调用音频模型，不生成 AI 旁白、角色对白、口型同步或个性化音乐。
- 忽略或移除视频供应商返回的原始音轨，避免七章声音风格和质量不一致。
- 使用一条本地预置的轻柔环境音乐，以及少量推门、风铃、翻页和合书 UI 音效。
- 声音只在用户完成首次开书点击后开始，并始终提供可发现的静音开关。
- 每章正文由网页 DOM 文字层呈现，不烧录进视频；文字可以随视频渐显，并在视频停止后继续保留。
- 声音不是理解故事的必要条件；音频加载失败时，七章仍可完整阅读。
